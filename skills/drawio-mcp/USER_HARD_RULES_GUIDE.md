# Draw.io 用户硬性要求执行指南（Ps-openspec Draw.io 最高根文件）

> **制度定位**：本指南为 Draw.io 绘图体系的**唯一最高法定根文件（Root Authority）**，归属 **Ps-openspec 轨道工程体系（Layer 3 契约立法 + Layer 2 机械门禁）** 管辖。**任何 Agent 使用 `drawio-mcp` 或 `scripts/drawio-toolkit.mjs` 前，必须首先完整读取本指南**。
> **演进机制**：用户后续提出的所有 Draw.io 绘制硬性要求，均须按 `DRW-09, DRW-10...` 递增编号追加至本文末《用户追加硬性要求变更台账》，并同步下沉至 `scripts/drawio-toolkit.mjs` 的 L2 校验器。

## 一、 八大法定硬性条款（`DRW-01` ~ `DRW-08`）

### `DRW-01`：统一黑白朴素工业风（严禁彩色杂乱）
- **核心铁律**：严禁使用红/绿/黄/蓝/紫等花哨多色填充或高饱和彩色边框，全图统一采用黑白灰朴素工业配色，通过**图形轮廓、边框粗细与虚实线型**区分语义。
- **法定单色白名单（Color Whitelist）**：
  - 节点填充：`#FFFFFF`（纯白，唯一默认填充）
  - 泳道/表头底色：`#FFFFFF` 或 `#F8F8F8` / `#F5F5F5`（极浅灰仅限泳道标题栏）
  - 主边框与连接线：`#000000`（纯黑，核心流程/门禁/总线）或 `#333333`（深灰，常规节点/边框）
  - 次要辅助边框/虚线：`#666666`（中灰，仅限副标题文字、单据/数据关联虚线）
- **L2 机械门禁**：`NON_MONOCHROME_STYLE_BLOCKED`（检测到白名单外的彩色十六进制色值直接阻断，退出码非零）。

---

### `DRW-02`：严格限制画布大小（以第 2 页为法定基准）
- **核心铁律**：严禁为了“躲避绕线”而随意放大画布、拉宽列距或拉高泳道，避免出现大面积空白与阅读缩放失真。
- **法定画布基准（锁定自第 2 页基准）**：
  - **画布尺寸基准**：`pageWidth = 3065`、`pageHeight = 1241`
  - **泳道池基准**：`width = 2985`、`height = 1161`
  - **栅格尺度基准**：标准列宽 `colWidth = 230`（或 `190~230`），标准泳道行高 `laneHeight = 225`（单行单层时 `140~225`）
  - **单页法定上限（Hard Ceiling）**：`pageWidth <= 3200`、`pageHeight <= 1300`（单页泳道池不超过 `3120 × 1220`）。
- **超限处置策略**：若业务节点过多导致超出上限，**必须拆分为多个关联子页（L1 -> L2）或精简为“子流程节点 (`sub`)”**，禁止突破单页画布上限。
- **L2 机械门禁**：`CANVAS_SIZE_EXCEEDED_BLOCKED`。

### `DRW-03`：严格界定线条、实体关系、高级等工具的使用场景
> 合适语义必须使用合适对象，严禁“拿 ER 线画业务流”或“拿普通矩形代替数据库/单据”。

#### 1. 基础图形与业务对象选型表
| 工具面板分类 | Draw.io 对象/形状 | IR `kind` | 唯一适用条件（When to Use） | 禁止误用场景（Do Not Use For） |
| :--- | :--- | :--- | :--- | :--- |
| **通用 / 流程图** | 圆角椭圆 (`ellipse`) | `start` / `end` | 仅用于流程的**唯一触发起点**或**最终闭环终点**（`end` 边框加粗 `strokeWidth=2` 区分） | 禁止用于中间业务步骤或状态标签 |
| **通用 / 流程图** | 直角/微圆角矩形 (`rounded=0/1`) | `process` | 单一职能角色执行的**原子业务活动** | 禁止用来表示表单单据、数据库或判断条件 |
| **通用 / 流程图** | 双竖线子流程 (`shape=process`) | `sub` | 需下钻到 L2 子图或跨模块引用的**复合子流程** | 禁止用于普通原子操作 |
| **通用 / 流程图** | 菱形 (`rhombus`) | `decision` | **二元或多元条件分支判断 / 阶段门禁 (Stage-Gate)**，必须带明确条件分支标签 | 禁止无分支的直通节点使用菱形 |
| **通用 / 实体** | 文档波浪底 (`shape=document`) | `document` | 流程中产生的**结构化表单、报告、审批单** | 禁止当做业务动作节点串联在主干流中 |
| **实体关系 / 高级** | 圆柱体 (`shape=cylinder3`) | `datastore` | **持久化台账、业务数据库或外部系统底座** | 禁止用来表示临时纸质/电子单据 |
| **高级 / 泳道** | 跨职能泳道 (`swimlane`) | `lanes` | **涉及 >=2 个部门/岗位/系统协同**的端到端业务流程 | 单一角色内部微步骤无需强行拆泳道 |

#### 2. 线条（Edges）使用边界矩阵
| 线条语义类别 | 线条样式规范 | 唯一适用条件（When to Use） | 禁止误用场景 |
| :--- | :--- | :--- | :--- |
| **主流程流转线 (`flow`)** | 实线、`strokeColor=#000000`、`strokeWidth=1.2`、实心箭头 | 正常正向业务流转、条件分支通过路径 | 禁止用于退回返修或纯数据关联 |
| **异常/返修/退回线 (`feedback`)** | 虚线 (`dashed=1`)、`strokeColor=#333333`、空心/普通箭头 | 驳回、验证失败返修、未通过回流、升级纳管 | 禁止与正向主干实线混用 |
| **单据/数据关联线 (`data`)** | 点虚线 (`dashed=1;dashPattern=2 3`)、`strokeColor=#666666`、无箭头或细箭头 | 业务活动节点 **垂直或侧向挂载** `document`/`datastore` | 禁止用业务主线穿过单据后再连下一个业务节点 |
| **系统集成总线 (`bus`)** | 加粗实线 (`strokeWidth=1.8`)、`strokeColor=#000000` | 核心系统与外部系统之间的 API 接口同步 | 禁止用于普通人工审批流转 |

#### 3. 实体关系（ER）与高级工具使用边界
- **实体关系（ER / `entityRelationEdgeStyle`）**：**仅限绘制数据库表结构、主数据实体字段及 `1:1 / 1:N / M:N` 基数关系**；严禁在 BPMN 业务流程图中混用 ER 鸡爪线（Crow's foot）。
- **高级容器 / 分组框（`group` / 虚线框）**：**仅限在非泳道架构图**中用于逻辑域边界归类；在泳道图中严禁再套多层嵌套虚线框造成视觉噪点。
- **注解（`shape=note`）**：仅用于补充说明业务规则阈值或异常处理备注，不得作为流程连线的起止端点。

### `DRW-04`：线条禁止横穿模块，避免线条交叉与拥挤
1. **零穿框铁律（Zero Box Crossing）**：任何连线线段不得穿过任何中间节点、单据框或非起止容器（`EDGE_CROSSES_NODE_BLOCKED = 0`）。
2. **禁止线条重叠与拥挤**：
   - 跨列/跨泳道连线必须严格走**列间垂直走廊**或**泳道间水平走廊**（Manhattan 正交绕行）；
   - 同一走廊内多条平行线段必须分配独立轨道，**最小物理间距 `>= 16px`（推荐 `20px–30px`）**；
   - 通过调整节点顺序或将静态单据/台账下沉至独立数据行/数据泳道，消除不必要的连线交叉。
3. **标签防压线**：连线文字标签（1–4 字短词）优先置于线段中段或分流近端空白处，不得与邻近线条交叉压字。

---

### `DRW-05`：线条对准模块中点，务必确保箭头指向中点
1. **中点锚定原则（Midpoint Principle）**：
   - 所有连线起点（`exitX/exitY`）与终点（`entryX/entryY`）**必须优先锚定在节点四边的正中点（`0.5`）**：
     - 水平流向：`exitX=1, exitY=0.5` → `entryX=0, entryY=0.5`
     - 垂直流向：`exitX=0.5, exitY=1` → `entryX=0.5, entryY=0`（或由下向上 `0.5,0` → `0.5,1`）
2. **严禁角点与偏心乱接**：禁止出现 `0.15`、`0.82` 或 `(0,0)`、`(1,1)` 等角点/偏心连接，确保**箭头尖端精确垂直指向目标模块边框中点**。
3. **多线分流处理**：当同一节点存在多条出线或入线时，优先分走**不同边中点**（如右中点 + 上中点 + 下中点），并通过走廊拐点分流，保证进入目标时仍汇入或垂直对准中点。
- **L2 机械门禁**：`NON_MIDPOINT_PORT_DETECTED`。

---

### `DRW-06`：禁用外部浏览器打开，直接在目标 `.drawio` 文件原地交付
- **核心铁律**：严禁调用会拉起外部浏览器（`app.diagrams.net`）的渲染通道或跳转脚本（如 `open_drawio_xml` 浏览器弹窗或 `open_multi_page.js`）。
- **法定交付通道**：所有图元生成与修改必须通过 `drawio-toolkit.mjs` 直接在用户指定的目标 `.drawio` 文件（单页 `build` 或多页 `replace-page` 原地替换）上落盘更新；如需本地预览，仅允许通过 `vscode-review:open_in_vscode` 在 VS Code 本地打开。

---

### `DRW-07`：从左到右（LR）坚持垂直居中，中心轴围绕画布水平中线
- **核心铁律**：所有从左到右（`LR`）流向的流程图与跨职能泳道图，必须坚持**垂直居中对称思想**：
  1. **全图居中**：整个模型图（泳道池或全节点外接矩形）的垂直中心轴线必须与画布水平中线（`pageHeight / 2`）对齐（允许偏差 `<= 20px`），上下留白对称；
  2. **泳道/列内居中**：泳道内或无泳道同层列内的单节点必须落在其水平中轴线上，多节点必须围绕水平中轴线对称排布。
- **L2 机械门禁**：`NON_VERTICALLY_CENTERED_LR`。

---

### `DRW-08`：单口出线直角分化原则（严禁多角伸出或错位茎叶图）
- **核心铁律**：当判断菱形或业务节点分化出多条下游分支时，**严禁从节点多个角点/边伸出，也严禁错位拉出多根平行“茎叶”线**；必须坚持**单线出线直角分化**：
  1. 节点统一从主出线边中点（`LR` 为右中点 `(1, 0.5)`，`TB` 为下中点 `(0.5, 1)`）引出**同一根主干线**至共享拐点 `trunkX` / `trunkY`；
  2. 所有下游分支均从该主干线上的共享拐点处做**精确 90° 直角分化**（T 型或十型正交分叉）接入各目标中点。

## 二、 纳入 Ps-openspec 执行体系的运行机制

1. **Step 1（根文件强制准入）**：任何涉及 Draw.io 的任务，首先完整读取本根文件 `USER_HARD_RULES_GUIDE.md`（`DRW-01`~`DRW-08`）及 `drawio-mcp/SKILL.md`。
2. **Step 2（Diagram IR 构造）**：严禁手算裸 `<mxCell>` 坐标；先构造结构化 IR JSON（遵循 `DRW-03` 对象与线条选型）。
3. **Step 3（L2 机械硬门禁）**：执行 `node "C:/Users/Administrator/.gemini/config/skills/drawio-mcp/scripts/drawio-toolkit.mjs" build/validate`，必须达成 **评分 `100` 且退出码 `0`**，方可通过门禁。
4. **Step 4（本地原地落盘交付）**：遵循 `DRW-06`，直接落盘或通过 `replace-page` 原地替换目标 `.drawio` 文件，可选通过 VS Code 本地预览；禁用外部浏览器弹窗。
