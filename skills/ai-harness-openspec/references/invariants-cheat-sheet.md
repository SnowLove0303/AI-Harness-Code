# 核心不变量与代码防篡改封印速查卡 (Invariants Cheat Sheet)

---

## 一、十大法定不变量 (The 10 Invariants)

1. **规格高于代码**：specs 是最高法定依据，代码错改代码，严禁先斩后奏。
2. **不可否定公理**：既有业务逻辑、回退分支、定制格式是经过确认的法定事实，严禁凭通用洁癖擅自重构或否定。
3. **源码级代码封印**：凡包含 `@ANTIGRAVITY_INVARIANT_LOCK` 标记的代码块，享有最高只读豁免权。
4. **正向行动化表述**：不写“粉色大象”负向禁令，一律用明确的准入动作与封闭作用域定义。
5. **最小因果集与保留现状**：改动严格限制在当前目标最小集合，周边历史告警保持原样。
6. **差分作用域与退出码 0**：改动范围严格受控于 git diff，打勾必须以真实退出码 0 为充要条件。
7. **VS Code 原生差异检阅**：任何源码修改必须通过 `review_diff_in_vscode` 经用户在原生两栏对比视图中把控。
8. **双重人工授权与验收归口**：动工前双清单授权门禁 + 交付后人工操作验收归口。
9. **问题与解法沉淀 (CHANGELOG 闭环)**：每次任务必须沉淀根因与解法，经验永续。
10. **专属引擎唯一路由公理**：有专用处理流水线的任务，严禁私自手写脚本直改底层业务产出物。

## 二、源码级封印标记使用规范

在关键逻辑、反直觉映射、易被误删的容错代码周围使用：

```javascript
// @ANTIGRAVITY_INVARIANT_LOCK_START: <保护原因与需求背景>
// 详细说明为什么这段代码必须这样写，防止后续 Agent 自以为是重构
...核心受保护代码...
// @ANTIGRAVITY_INVARIANT_LOCK_END
```
Python / Shell 语法等效使用 `# @ANTIGRAVITY_INVARIANT_LOCK_START` 与 `# @ANTIGRAVITY_INVARIANT_LOCK_END`。
