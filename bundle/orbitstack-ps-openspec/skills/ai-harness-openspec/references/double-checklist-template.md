# 前置双清单汇报标准模版 (Double Checklist Template)

在进入任何代码编写前，Agent 必须在对话框中向用户呈报以下格式的双清单，并等待用户明确确认：

```markdown
### 📋 OpenSpec 变更方案与执行前双清单呈报

> **提案名称**：`<change-name>`  
> **关联工件**：`openspec/changes/<change-name>/proposal.md`

---

#### 1. 拟变更范围清单 (Proposed Scope Checklist)
- **受影响文件清单**：
  - `path/to/file1.ext` (行号/函数范围)
  - `path/to/file2.ext` (行号/函数范围)
- **核心调整逻辑**：
  - [简要说明要做什么改动]
- **细粒度任务与验证凭据 (`tasks.md`)**：
  - [ ] 1.1 `任务描述` ── 验证依据：`npm run test:...` (必须退出码 0)
  - [ ] 1.2 `任务描述` ── 验证依据：`review_diff_in_vscode` 检阅通过
- **受影响范围边界**：
  - 仅限于当前变动模块，绝不越界修改无关文件。

---

#### 2. 保持现状承诺清单 (Preserved Functionality Commitments)
- 🔒 **既有功能承诺**：承诺绝不修改、弱化或否定现有功能 `[功能名称]` 的业务逻辑；
- 🔒 **封印代码承诺**：承诺绝不触碰任何标记有 `// @ANTIGRAVITY_INVARIANT_LOCK` 的受管代码块；
- 🔒 **核心门禁承诺**：承诺严格保持现有测试、合规断言与构建门禁 100% 绿灯；
- 🔒 **专属引擎承诺**：承诺所有产出物均经官方受控流水线生成，绝不手写脚本直改底层文件。

---

**请确认上述方案与承诺清单。收到您的明确指令（如“执行”、“确认”或“同意”）后，将立即启动第一步施工。**
```
