# Proposal: Canonical Entrypoint Invariance & Throwaway Script Proliferation Governance

## Summary
Establish formal software engineering legislation, Layer 1 constitutional axioms, and Layer 2 automated linter guardrails to eliminate the systemic pathology where AI agents bypass canonical entrypoints, generate scattered throwaway scripts, and fragment execution paths during workflow development and iterative optimization.

## Problem Context & Motivation
In practical agentic coding and workflow engineering, agents repeatedly exhibit three critical anti-patterns:
1. **Bypassing Canonical Entrypoints**: Instead of routing through the official dispatcher, production gateway, or MCP interface, agents bypass the frontdoor to directly invoke internal unexported scripts or arbitrary subroutines, leaving core frontdoors unexercised and untracked.
2. **Proliferation of Throwaway Scripts**: When encountering edge cases, bugs, or parameter adjustments, agents reflexively create scattered ad-hoc scripts (e.g., `temp_fix.js`, `run_patch.py`, `debug_quick.mjs`) in repository root or source folders. These create false isolated passes ("island pseudo-pass"), generate severe technical debt, and leave messy unmaintained files.
3. **Absence of a Single Canonical Execution Path**: Because multiple ad-hoc execution paths exist, workflows fail to converge into predictable, auditable state machines and cannot be reliably crystallized into reusable action skills.

By enforcing the **Canonical Entrypoint Invariance & Anti-Script Proliferation Axiom** (Axiom 55), all workflow tasks MUST strictly flow through the designated canonical entrypoint, temporary exploration must remain strictly quarantined in sandboxed locations with mandatory crystallization or purge upon delivery, and bug fixes/optimizations must be hardened in-place within core dispatchers rather than wrapped in external band-aids.
