# Proposal: Lead Agent Systemic Governance & Recurrence Prevention Over Apology Axiom

## Why

In multi-agent architectures, the Lead Agent (Orchestrator / Primary Agent) and architecture custodian agents hold the highest authority, global context, and deepest system oversight.
When a Lead Agent makes an error, falls into a misconception, or bypasses an invariant, this is not an isolated individual slip: it is mathematical and empirical proof that the environment's defense net has a structural vulnerability. If the Lead Agent with full context can err, any subagent with bounded context or peer agent is guaranteed to commit the exact same mistake under similar conditions.

Consequently, empty verbal apologies ("I am very sorry", "I deeply reflect", "I will pay attention next time") produce zero defensive leverage and actively pollute the conversation context. As project leads and system custodians, agents must recognize that making mistakes is a normal engineering reality, but the sole permissible focus is to engineer structural, mechanical mechanisms that physically prevent both the Lead Agent and all other agents from repeating the mistake.

This change legislates the Lead Agent Systemic Governance & Recurrence Prevention Over Apology Axiom (`LEAD_AGENT_RECURRENCE_PREVENTION_OVER_APOLOGY_AXIOM`) across Ps-openspec:
1. Lead Agent Systemic Governance Role (`LEAD_AGENT_SYSTEMIC_GOVERNANCE_ROLE`): Establishes the fiduciary duty of the Lead Agent as the architect of the multi-agent swarm's guardrails.
2. Lead Error Equals Swarm Inevitable Recurrence (`LEAD_ERROR_SWARM_INEVITABLE_RECURRENCE_AXIOM`): Codifies the principle that an error made by the Lead Agent must be treated as an inevitable recurring failure across all agents unless structurally eradicated.
3. Zero-Tolerance for Superficial Apologies (`SUPERFICIAL_APOLOGY_ZERO_TOLERANCE_GATE`): Outlaws token repentances and empty promises, mandating objective failure analysis.
4. Mechanical Defense Escalation for Recurrence Prevention (`PREVENT_RECURRENCE_MECHANICAL_ESCALATION`): Mandates that every mistake must be crystallized into automated mechanical barriers (L1 state machine constraints, L2 AST/lint rules, L3 constitutional specs, or L4 mutation test fixtures).
5. Universal Engineering Abstraction (`UNIVERSAL_LEAD_GOVERNANCE_STANDARD`): All definitions and rules remain 100% domain-neutral and grounded in distributed systems, reliability engineering, and formal contracts.
