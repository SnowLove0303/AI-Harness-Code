# Change Proposal: UI Craft Elevation, Distill Purification & Automated L2 UI-Slop Guard (Axiom 73)

## Why
Existing static UI guidelines lack executable enforcement and allow AI coding agents to generate plain default scaffolds, redundant explanatory prose, excessive eyebrow/badge clutter, and lazy identical card grids. By synthesizing the strongest principles from `pbakaus/impeccable` (`craft-floor`, `distill`, `bolder`, `polish`, `mode-operate/read/persuade`), `nextlevelbuilder/ui-ux-pro-max-skill` (design intelligence), and `vercel-labs/agent-skills` (`web-design-guidelines`), and backing them with a deterministic Layer 2 static guard (`scripts/check-ui-slop.mjs` / `npm run guard:ui-slop`), Ps-openspec gains mechanical enforcement against UI slop and visual plainness.

## What Changes
1. **REQ-1 (Upgrade UI/UX Engineering Skill Engine)**: Upgrade `skills/ui-ux-design-engineering/SKILL.md` with `impeccable` craft-floor standards (browser surface polish, `tabular-nums`, contrast, type measure, depth offsets, zero gradient text/default glassmorphism, zero lazy card grids/nested cards) and `ui-ux-pro-max` intentional aesthetic direction.
2. **REQ-2 (`distill` Purification & Zero-Bloviation Discipline)**: Mandate a dedicated `distill` pass banning eyebrow/kicker labels above every heading, explanatory prose paragraphs inside operational components, excessive decorative badges, and meaningless `01/02/03` section markers.
3. **REQ-3 (Automated L2 UI-Slop Static Guard)**: Create `scripts/check-ui-slop.mjs` (`npm run guard:ui-slop`) supporting multi-framework templates (`.tsx`, `.jsx`, `.vue`, `.svelte`, `.html`, `.css`) to deterministically detect nested cards, excessive badge density, verbose explanatory prose blocks, eyebrow clutter, and default purple-glow AI-slop templates.
4. **REQ-4 (Axiom 73 Three-Mirror Codification)**: Codify Axiom 73 (`UI_CRAFT_DISTILL_&_AUTOMATED_SLOP_GUARD_AXIOM`) identically across `GEMINI.md`, `skills/pstack-openspec/SKILL.md`, and `skills/ai-harness-openspec/SKILL.md` (Invariant 70) using pure universal software engineering abstractions.
5. **PROP-C (Three-Mode Density Budgeting)**: Support `operate`, `read`, and `persuade` UI mode awareness to prevent false positives on high-density operational consoles or editorial reading layouts.
6. **PROP-D (`Shape -> Distill -> Polish` Tri-Phase Execution Lock)**: Enforce the sequential UI craft workflow in `worker.md` and `skills/ui-ux-design-engineering/SKILL.md`.
7. **PROP-E (Cross-Framework Component-Level Density Scanning)**: Ensure `check-ui-slop.mjs` reports exact file/line diagnostics with clear remediation hints.
