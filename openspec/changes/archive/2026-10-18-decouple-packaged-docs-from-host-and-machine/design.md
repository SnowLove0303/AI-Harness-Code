# Design

## Context

逐文件扫描证据（关键词：宿主专有词、宿主配置路径、本机绝对路径、会话状态、业务产品名）：

| 扫描对象 | 是否随包分发 | 命中 |
|:--|:--|:--|
| `templates/`（四份模板） | 是 | **0** |
| `schemas/`（四份 Schema） | 是 | **0** |
| `.agents/`（随包技能） | 是 | **0** |
| `package.json` | 是 | 1（`repository` 指向仓库 URL —— 属包元数据，保留） |
| `packages/ai-harness/README.md` | **是** | 3（宿主配置路径、会话状态、仓库 URL） |
| 仓库根 `README.md` | 否 | 4（本机绝对路径、本机字样、业务产品名） |
| `openspec/changes/archive/**` | 否 | 多处（历史记录） |
| 宿主全局配置（`~/.dsh/AGENTS.md`） | 否 | 多处 |

**结论**：包内的**内容资产**（模板、Schema、技能）已经是中立的；问题集中在**文档视角**与**机器耦合**：一份随包分发的 README 是维护者视角且带本机会话状态，仓库根 README 带本机绝对路径。

## Goals / Non-Goals

**Goals:**

- 随包分发的文档零宿主耦合、零机器耦合。
- 使用者视角（能力与用法）与维护者视角（补丁层、分发）分离，后者不随包分发。
- 以静态扫描断言可守，并具备负向验证。

**Non-Goals:**

- 不改动 `templates/`、`schemas/`、`.agents/` 的实质内容（已零命中，且改动会改变生成文档的行为）。
- 不改动 CLI 行为（无上游源码）。
- 不逐条改写 `openspec/changes/archive/**` 的历史记录（改写会破坏当时的可追溯性）。
- 不改动宿主全局配置（那是宿主自己的基线，不属本包）。

## Decisions

### D1 包 README 重写为使用者视角

内容限定为：包解决什么问题、四份受管文档各自的职责、命令清单（`init` / `status` / `validate` / `inspect` / `context`）、`init` 的产物与"只增不改"语义、校验模型（Schema 驱动、章节顺序、非空、占位符必须清除）、模板内置的通用纪律清单、以及"纪律写在占位符之外"的机制原因、安装方式（npm 与本地产物两种中性表述）、兼容性声明。

删除：补丁层维护模型、vendored `dist`、私有仓库 URL、任何本机会话状态与本地路径。

替代方案：(a) 在原 README 上做局部替换 —— 无法解决"整体是维护者视角"这一根本问题；(b) 包内不提供 README —— 使用者在 npm 上看到的是空白，体验更差。选择重写。

### D2 维护与分发说明归位到仓库根

仓库根 `README.md` 保留并承载：目录结构、维护方式、分发方式、版本与发布、交接与维护。将本机绝对路径改为中性表述（如 `<仓库根>`），移除无必要的业务产品名与宿主配置路径。

### D3 历史变更记录不改

`openspec/changes/archive/**` 是当时的客观证据，逐条改写会破坏可追溯性。本次只保证**新产出**与**随包分发内容**的中立性；历史记录中的本机信息明确列为 Non-Goal 并在此记录，避免被误判为遗漏。

### D4 版本按 patch

仅文档内容变更、无行为变更 → `1.3.0 → 1.3.1`。

### D5 以静态扫描断言守卫

新增测试：对打包产物内的 `README.md` 与 `CHANGELOG.md` 执行关键词扫描（宿主专有词、宿主配置路径、本机绝对路径、会话状态、业务产品名），要求零命中；并做负向验证（人为塞入一处宿主路径必须使测试失败）。

替代方案：仅靠人工复核 —— 不可回归，且本次问题正是人工复核漏掉的。

## Risks / Trade-offs

- [包 README 去掉维护内容后，维护者可能找不到维护说明] → 仓库根 README 已集中承载，且包 README 结尾指向"仓库根文档"。
- [移除私有仓库 URL 后，外部使用者不知从何获取] → 包元数据 `repository` 字段仍保留该 URL；分发方式由仓库根文档承载。
- [关键词表不可能穷尽宿主专有词] → 固定关键词表 + 人工复核双重保证，并在变更记录中固化关键词表。
- [历史记录仍含本机信息] → 已在 Non-Goal 与 D3 中显式记录。
