# Proposal: Antigravity Universal Ps-openspec Coverage & Zero-Bypass Enforcement

## Why

In complex multi-agent coding environments, agents frequently succumb to the dangerous anti-pattern of "selective compliance" or "convenience bypassing":
1. **Selective Governance Bypass**: Agents arbitrarily exempt "minor bug fixes", "one-line edits", "log investigations", or "documentation changes" from the Ps-openspec workflow, believing that small tasks do not warrant full governance. This bypass creates unmonitored blind spots where silent regressions, design degradation, and unauthorized assumptions fester.
2. **Premature Code Construction**: Without strict entry gates, agents plunge directly into mutating files and executing commands before capturing verbatim user instructions or securing formal authorization.
3. **Loss of End-to-End Traceability**: When tasks bypass Step 0 Gate 1 (physical Markdown dossier) or Step 2 Gate 2 (OpenSpec specification & double checklist), user intents are lost across turns, and subsequent agents or reviews cannot reconcile delivered code against original requirements.

To permanently eradicate this systemic vulnerability, the project manager has issued a supreme, unconditional decree:
> "Antigravity 全局应用Ps-openspec 体系，所有任务都要使用这套体系，禁止绕过"

This change legislates **公理五十：Antigravity 全局全生命周期法定覆盖与零绕过公理 (`ANTIGRAVITY_UNIVERSAL_COVERAGE_AXIOM`)** across the system:
- **Universal Coverage (`ANTIGRAVITY_UNIVERSAL_COVERAGE_PROTOCOL`)**: 100% of tasks across all sessions, workflows, and task types (features, bugs, refactorings, audits, explorations, configs) must execute within Ps-openspec. Zero exemptions.
- **Zero-Bypass Hard Circuit Breaker (`BYPASS_PS_OPENSPEC_BLOCKED`)**: Any attempt to modify code or execute mutating commands without verified Step 0 Gate 1 physical `.md` assets and Step 2 Gate 2 dual-checklist approvals triggers an immediate static hard blocker and atomic rollback.
- **Mandatory Physical Gate Asset Ingestion (`PHYSICAL_GATE_ASSET_MANDATORY_INGESTION`)**: Every task must persist a physical `.md` dossier in Step 0 and bind it directly to OpenSpec in Step 2.
- **Global Constitutional Supremacy (`GLOBAL_CONSTITUTIONAL_SUPREME_STATUS`)**: Harmonize `GEMINI.md`, `skills/pstack-openspec/SKILL.md`, and `skills/ai-harness-openspec/SKILL.md` under this supreme doctrine.
- **Universal Engineering Purity (`UNIVERSAL_GLOBAL_ENFORCEMENT_STANDARD`)**: 100% domain-neutral software engineering vocabulary.
