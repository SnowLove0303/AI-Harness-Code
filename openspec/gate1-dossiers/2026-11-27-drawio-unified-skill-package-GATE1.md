# Gate 1: 需求全量对账备忘录 (`drawio-unified-skill-package`)

## 1. 原始用户指令（100% 逐字留存 · 事实指纹）
> 「做个统一的技能包吧，然后给我提示词我让Agent看技能包就行了」

## 2. 1:1 需求物理对账矩阵 (RTM)

| 需求 ID | 原始需求拆解 | 场景故事 (Scenario Story) | 详细功能契约 (Functional Contract) | 独立验收指标 (Acceptance Criteria) |
|---|---|---|---|---|
| **REQ-01** | 制作统一的 Draw.io 技能包 | 作为交付流程给其他 Antigravity Agent 使用的协调者，我希望所有 Draw.io 绘图规范、确定性布局编译器、几何校验器与 MCP 协同指令都收敛在同一个技能包内，使任意工作区的 Agent 无需跨目录寻找仓库脚本即可开箱即用。 | 技能包应实现自包含（Self-Contained）：内聚主指令文档、可独立执行的工具脚本、标准输入输出示例/模板，并通过全局同步机制保持权威仓库与全局技能目录一致，不破坏既有跨仓库调用与现有测试。 | 任意工作区下的 Agent 仅依据技能包自身目录即可完成 IR JSON -> 编译 `.drawio` -> 几何评分校验 -> MCP 渲染交付全链路，且现有 Draw.io 测试与静态守卫全部通过（Exit Code 0）。 |
| **REQ-02** | 提供极简交付提示词 | 作为使用者，我希望拿到一段简短清晰的提示词，只需让 Agent 阅读并使用该统一技能包，即可自动按 Ps-openspec Draw.io 体系高质量画图。 | 提示词应直接指向统一技能包名称/入口，清晰传达业务需求占位符与核心验收要求，无需在提示词中堆砌冗长脚本路径或重复规则细节。 | 用户复制提示词并填入业务流程描述后，Agent 能准确触发并完整执行统一技能包的全部规范流程。 |

## 3. 前瞻性头脑风暴扩展提案清单 (Proactive Brainstorming Proposals)
- **提案 A（跨工作区零依赖自包含）**：在技能包内提供 `scripts/` 与 `references/`（或示例 IR 模板），确保即使 Agent 当前处于完全无关的业务仓库中，也能直接调用技能包自带的编译器与校验器，而无需依赖 `AI-Harness-Code` 仓库路径。
- **提案 B（标准 IR 模板与常见图型示例内置）**：在技能包内附带标准流程图与跨职能泳道图的最小可运行 IR JSON 模板，降低 Agent 首次构造 IR 时的字段拼写错误率。
- **提案 C（双通道 MCP 自动降级/选型指引）**：在技能包内明确 `drawio`（本地/桌面 XML 渲染）与 `drawio-cloud`（云端渲染）的调用优先级与参数映射，避免 Agent 在可用 MCP 之间犹豫或误用纯手写 XML。
- **提案 D（单一权威源同步与零漂移）**：将统一技能包纳入既有全局同步流，保证仓库版本与全局安装版本始终一致，避免出现“改了仓库忘了同步全局”或双份内容漂移。
